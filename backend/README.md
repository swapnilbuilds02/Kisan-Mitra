# Phase 1 backend shell

Install with `python -m pip install -r backend/requirements-dev.txt` from the repository root, then run `python -m pytest backend/tests -q`. For a local API, set `JWT_PRIVATE_KEY_PEM`, `JWT_PUBLIC_KEYS_JSON`, `JWT_ACTIVE_KID`, and `DATABASE_URL` (an API login inheriting `km_api`); run `python -m uvicorn backend.app.main:app --reload`. Do not place private keys in the repository or use a migration-owner connection at runtime.

The API exposes liveness/readiness, purpose-bound OTP routes, shared password login, recovery/change, refresh, logout, protected profile/overview routes, Farmer onboarding, partner applications/approval, and restricted Admin activation. Sessions use the PostgreSQL functions from `0002` onward. Password login requires `PASSWORD_RATE_PEPPER` of at least 32 bytes. Farmer and approved partners can authenticate; pending partners get restricted sessions. Admins must also have an activated `admin_provisioning` record. No SMS sender is selected automatically. Missing configuration and backend errors deny protected access.

`migrations/0001_identity_foundation` through `0008_admin_identity` are versioned schema slices. Apply them in order to a **disposable** PostgreSQL database first, using a separate migration owner with `CREATEROLE`, then grant its API login membership in `km_api`. No Stage 1E schema file has been executed on a live database. Tables have RLS enabled with no direct runtime grants; narrow security-definer functions are granted explicitly. Database credentials, private signing keys, `OTP_PEPPER`, and `PASSWORD_RATE_PEPPER` must remain private. An approved SMS sender must be injected explicitly before OTP delivery can work. Farmer and partner onboarding require approved consent document versions; no production document is seeded.

Initial Owner preparation is a **migration-owner-only** command. On a private operator machine, set `ADMIN_PROVISION_DATABASE_URL` to the migration-owner connection for the intended environment and run `python -m backend.app.admin_provision --bootstrap-owner --mobile <REGISTERED_MOBILE> --display-name <NAME>` from the repository root. This only creates an inactive, unverified identity; it does not set a password or issue a session. Mobile ownership must then be proved through `/api/v1/auth/admin/activate/request`, `/verify`, and `/complete` with an explicitly configured OTP delivery adapter. The completion token expires after 10 minutes and can be used once. A later Admin may be prepared only through the same privileged command using `--operator-id <ACTIVE_OWNER_UUID>`; the operator must independently verify the Owner's authorization. Do not place the migration-owner connection in the API environment or commit it. No actual Owner account has been provisioned in this repository. Stage 1E rollback is recovery from a tested database snapshot or recreation of the named disposable test database; no production rollback has been verified.

See [Phase 1 authentication/database verification](../docs/PHASE1_AUTH_DB_VERIFICATION.md) for the integration test procedure, architecture decisions, and open security gates.

Stage 2A adds `POST/GET /api/v1/farmer/plots`, `GET/PATCH /api/v1/farmer/plots/{plot_id}`, and `POST /select` or `/archive` plus `GET /weather/context` for an active own plot. Apply `migrations/0009_farmer_plots.up.sql` only after 0008 in a disposable database first. The API verifies an active Farmer session and passes that identity to narrow database functions; no partner plot route is enabled. Weather returns `unavailable` until a separately approved provider is injected. See [Stage 2A](../docs/STAGE2A_PLOTS_WEATHER.md) for constraints, location permission, and the guarded integration test.
